# 00 — North Star

## Product Promise

> **Build your idea for the lowest practical cost.**

CAOS (Cost-Aware Orchestration System) finds and, when authorized, executes the lowest-cost practical path from a user's software idea to a working, verified product.

## Mission

Build an autonomous software-development orchestration system that researches a user's idea, decomposes it into tasks, discovers legitimate free, open-source, trial, discounted, and paid resources, evaluates capability/cost/reliability/availability, creates an economically optimized execution plan, and either builds the product or gives the user a detailed DIY roadmap.

## Core Question

> **What is the cheapest reliable way to complete this task while satisfying the user's quality, functionality, security, and time requirements?**

CAOS should answer this continuously at task level rather than selecting one provider at the beginning and blindly using it throughout execution.

## Two Product Paths

### Path 1 — Let CAOS Build It

CAOS researches, plans, executes, verifies, recovers from failures, and delivers the software artifact. The user receives an estimated cost, timeline, resource plan, risks, and final deliverable.

### Path 2 — Show Me How

CAOS provides a detailed, cost-optimized implementation roadmap that the user can execute themselves, including architecture, tools, free/cheap resources, setup sequence, prompts/instructions, expected costs, alternatives, and troubleshooting guidance.

## Legitimate Cost Minimization

CAOS optimizes cost using resources and pricing mechanisms that are legitimately available to users, including free tiers, public trials, open-source/local models, published discounts, low-cost APIs, and sensible provider switching. It must not circumvent rate limits, evade payment controls, abuse trials, or violate provider terms.

## North Star Outcome

A user provides an idea and constraints such as budget, quality, deadline, and preferred autonomy. CAOS researches the ecosystem, decomposes the idea, evaluates resources, produces two clear options, and—if authorized—executes the lowest-cost practical build path while preserving state across agents and verifying the result.

## Optimization Objective

Conceptually:

**Minimize total cost** subject to:

- Required functionality being achieved
- Minimum acceptable quality
- Acceptable reliability
- Acceptable security
- User-defined time constraints
- Legitimate use of external resources

## North Star Metric

**Quality-adjusted cost efficiency:** useful, verified software outcome achieved per unit of legitimate AI/infrastructure cost.

Supporting metrics:

- Total cost
- Cost per successful task
- Build success rate
- Verification pass rate
- Execution time
- Token consumption
- Number of handoffs
- Context-retention score
- Failure/recovery rate
- Free-resource utilization
- Paid-resource avoidance where quality is maintained

## Long-Term Vision

CAOS evolves from a cost-aware agent router into an autonomous AI software-development operating system capable of researching, planning, architecting, coding, testing, reviewing, recovering, and eventually deploying software with controlled human oversight.

## What CAOS Is Not

- Not merely an n8n workflow.
- Not a chatbot with multiple prompts.
- Not a static list of AI providers.
- Not a system whose purpose is to abuse free tiers.
- Not a guarantee that every project will always be cheaper than every alternative.
- Not an unrestricted autonomous production deployer in early versions.

## Strategic Constraint

Budget is both a product constraint and a research variable. Paid services should be introduced only when their incremental capability produces measurable value relative to cost. CAOS should optimize for the **lowest practical cost**, not the lowest nominal price at any cost.
